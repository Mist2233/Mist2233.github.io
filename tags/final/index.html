final和override关键字

关键字 override 没有 override 时存在的风险 面试官： 在 C++11 之后，我们在处理类的继承和虚函数时，多了 override 和 final 这两个说明符。我们先来聊聊 override。 请看下面这段代码： class Base { public: virtual void doSomething(int param) { /* ... */ } }; class Derived : public Base { public: // 这里有一个小小的笔误，程序员将int写成了long virtual void doSomething(long param) { /* ... */ } }; 在 Derived 类中，程序员的意图是重写 (override) 基类的 doSomething 函数。但由于笔误，他把参数类型从 int 写成了 long。 请问，在没有 override 关键字的情况下，这段代码能编译通过吗？如果能，它在多态调用时，可能会产生什么样的问题？ 回答： 我认为编译能够通过。由于参数列表不同（这里是参数类型不同），编译器会认为程序员在 Derived 类中重载了一个虚函数。 可能的问题：在多态调用时，会出现函数参数实际类型不一致的情况，可能导致冲突。 面试官 (补充与解释): 你说的很对。我们来把这个问题分析得更透彻一些。 为什么能编译通过？ 因为编译器看到 Derived::doSomething(long) 时，它并不认为你是在“重写”。由于参数列表不同 (long vs int)，编译器会认为你是在 Derived 类里定义了一个全新的、和基类函数重载 (overload) 的虚函数。 ...
