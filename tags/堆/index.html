栈、堆与栈溢出

栈和堆的比较 Stack and Heap 面试官： 我们知道，C++ 程序在运行时，局部变量通常分配在栈 (Stack) 上，而动态分配的内存则来自堆 (Heap)。 请你从内存管理方式、分配效率、空间大小和数据生命周期这四个角度，详细对比一下栈和堆的主要区别。 回答： 在内存管理方式上，栈的内存是自动分配、释放的连续空间，而堆的内存是需要程序员手动分配、释放的非连续空间。 在分配效率上，栈的分配效率比堆更高。 在空间大小上，栈的空间大小比堆更小，当栈达到一定深度，就会发生溢出。 在数据生命周期上，栈的生命周期更短，通常是一次函数调用开始时，栈空间被分配，而该次函数调用结束时，栈的内存就被释放。而堆上的内存，通常在整个程序的生命中始终存在，直到我们手动释放它。 栈溢出 Stack Overflow 面试官 (深入追问): 好的，你对基础区别已经很清楚了。我们来深入聊聊你提到的 “栈溢出 (Stack Overflow)”。 你刚才说“当栈达到一定深度，就会发生溢出”。这通常是由无限递归或过深的递归导致的。 我的问题是： 除了递归，还有没有其他常见的编程行为，也可能导致栈溢出？你能否写一个不使用递归的、非常简单的代码片段，来人为地触发一个栈溢出？ 回答： 可以，除了递归之外，两个函数无限制地相互调用也可以出发栈溢出，比如下面的例子。 void funcA(); void funcB(); void funcA() { funcB(); } void funcB() { funcA(); } int main () { funcA(); return 0; } 面试官 (继续引导): 很好。不过，我们还能不能让问题变得更“纯粹”一点？ 我的意思是，在单个函数内部，不调用任何其他函数（甚至不调用自己），有没有办法在栈上一次性地分配一个巨大的内存块，从而直接导致栈溢出？ （提示：什么样的局部变量会占用大量的栈空间？） 回答： 我明白了，可以通过在函数内部分配一个巨大的数组，来耗尽栈空间，从而实现栈溢出。比如下面的例子： void func() { int bigArray[10000000000000000]; } int main() { func(); return 0; } 完全正确！这正是我想引导你找到的答案。 ...
