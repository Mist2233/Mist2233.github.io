Const关键字

const 的基本作用 我能想起来的 const 作用： 标记常量。 标记只能“读取”而不能“修改”的类函数。 在参数引用时，标记不能修改的参数。 为什么推荐用 const 而不是 #define 来定义常量？ 我的理解： const 比 #define 更智能。 #define 是机械的、文本意义上的替换，你举的例子相当于把所有的 b 都替换成 10，这会带来一些运算上的问题，比如优先级之类的。 const 更加智能。但是具体原理我也说不清楚，希望面试官补充一下。 更加详细的补充：#define 是预处理器在编译前做的简单文本替换，它不理解 C++ 的语法。而 const 是 C++ 语言本身的一部分。 类型安全：const 定义的变量可以识别类型，但是 #define 做不到。 作用域：const 遵循 C++变量作用的规则，但是 #define 不会，容易造成命名冲突。 调试方便：const 定义的变量是有名字的，调试时可以看到。 C++特性兼容：const 变量可以取地址、作为引用传递。 总结一下就是： 在 C++ 中，尽可能用 const (或 enum) 来替代 #define，因为 const 更安全、更规范、更易于维护。 const 搭配指针使用 const int* p; int* const p; const int* const p; 上面三种用法的区别是？ 我认为，需要看 const 声明修饰的是指针本身，还是指针指向的内容： const int* p 中，const 直接修饰 int，可以结合为 const int 所以表示指向的变量的类型为 const int，即“指向常量的指针”。(pointer to const) 含义：不能通过 p 来修改其指向的值，但是 p 本身的值可以修改，即可以指向其他地址的变量。 int* const p 中，const 直接修饰指针 p，所以表示指针值不可变，即“常量指针”。(const pointer) 含义：p 本身是常量，不能被修改，但是 p 指向的内容的值是可以修改的。 而 const int* const p 结合了上述两种情况，表示“指针值为常量，指向的变量也为常量”。 const 和 & 结合 面试官 (最终问题): 很好，你对 const 和指针的结合理解得很透彻。现在我们把你最早的回答串联起来。 ...

Cpp内存管理

Cpp 内存分区 你能简单介绍一下 C++ 程序的内存分区吗？一个 C++ 程序在运行时，它的内存大概被分成了哪几个区域？ 回答： Cpp 程序运行时，分成堆、栈，以及全局的静态区域。 栈中的数据在函数调用结束时，就自动被释放。 堆中的数据由程序员自己分配，自己释放。 全局的静态区域在整段程序结束时，自行释放数据。 请问，我的理解正确吗？ 基本正确，但还需要补充： 面试官 (补充与细化): 你说的完全正确。为了让这个回答更完整、更专业，我们通常会把内存分区说得更细一些，一般分为五个区。你提到的三个区是其中最重要的，我帮你补充另外两个。 一个典型的 C++ 程序内存布局： 栈区 (Stack)： 存放：函数的参数值、局部变量等。 管理：由编译器自动分配和释放。 特点：函数调用时入栈，函数返回时出栈，分配速度快，但空间有限且是连续的。 堆区 (Heap)： 存放：程序运行时动态分配的内存，比如通过 new 或 malloc 创建的对象。 管理：由程序员手动分配 (new) 和释放 (delete)。如果忘记释放，就会造成内存泄漏。 特点：空间大，不连续，分配和释放速度相对较慢。 全局/静态存储区 (Static Storage Area)： 存放：全局变量和静态变量 (包括全局 static 变量和函数内 static 变量)。 管理：在程序编译时就已经分配好了，在程序整个运行期间都存在，程序结束时由操作系统释放。 常量存储区 (Constant Storage Area)： 存放：常量，特别是字符串常量 (e.g., "hello world")。 特点：内容只读，不允许修改。 代码区 (Code Area / Text Segment)： 存放：编译后的二进制机器代码。 特点：只读，且可共享。 你能把这五个区记住，在面试时就能给出一个非常全面和专业的回答。 堆和栈的对比 面试官 (深入提问): 好的，你对内存分区已经很清楚了。我们来聚焦于堆 (Heap) 和栈 (Stack) 的对比。 ...
